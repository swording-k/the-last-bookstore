## 一、游戏概述

### 1.1 一句话描述
在数字文明崩塌后的世界，你经营小镇上最后一家书店。每个来访者带着各自的困境到来，而你推荐的每一本书，都可能改变一个人的人生轨迹。

### 1.2 核心体验关键词
- **温暖治愈** — 不是末日废土的绝望，而是人性微光
- **书籍连接** — 通过推荐书来理解人、帮助人、影响人
- **经营成长** — 书店因你的选择而变化，小镇因书店而改变

### 1.3 目标平台
纯前端 Web 游戏（HTML5 + CSS3 + JavaScript），无需构建工具，浏览器打开即玩。

### 1.4 目标用户
18-30岁，喜欢叙事独立游戏的玩家。

## 二、世界观设定

### 2.1 背景故事 — "大断联" (The Great Disconnect)

204X年，一个普通的周二下午，全球数字网络同时永久失效。
所有服务器宕机、云端数据蒸发、电子设备变成废铁。
人类一夜之间回到了 analog 时代。

没有人知道原因。有人说太阳风暴，有人说量子坍缩，有人说是上帝按了重启键。
重要的是：**纸质书籍成了最珍贵的知识载体。**

### 2.2 橡木镇 (Oakhaven)

- 人口约800人，山区河谷小镇，距最近城市120公里
- 有一所小学、一间诊所、一个钟表作坊、一座老火车站
- 慢节奏、邻里熟识、彼此依赖

### 2.3 墨香书店 (Ink & Page)

- 祖父开了42年，3个月前去世
- 约60平米两层（一楼营业+阁楼仓库）
- 藏书约2000册
- **方圆百里唯一的书店**

### 2.4 玩家身份

继承了祖父的书店。祖父的信里写着：
> "这家店的价值不在于卖了多少本书，
> 而在于对走进来的每一个人，
> 给出了正确的那一句回答。"

## 三、核心玩法机制

### 3.1 每日循环流程

```
每天开始 → 开店 → 顾客到来(2-3人/天) → 对话倾听 → 推荐书籍 → 命运反馈 → 打烊写日记 → 下一天
```

### 3.2 推荐匹配等级

| 等级 | 条件 | 效果 |
|------|------|------|
| 🌟 完美匹配 | 书籍主题与顾客困境高度相关 + 正确对话回应 | 希望值+8~12，声誉+5 |
| ✅ 好推荐 | 主题相关但非最优解 | 希望值+4~7，声誉+2 |
| ➖ 一般 | 勉强沾边 | 希望值+1~2 |
| ❌ 不匹配 | 完全无关 | 希望值-3~-5 |

### 3.3 双维度进度

- **希望值 (Hope)**: 0-100，反映小镇精神状态，影响结局走向
- **声誉 (Reputation)**: 无上限，解锁新顾客/稀有书籍/隐藏剧情

### 3.4 每日多顾客系统

| 天数 | 顾客数量 |
|------|---------|
| Day 1-2 | 2人/天 |
| Day 3-4 | 2-3人/天 |
| Day 5+ | 2-4人/天 |

### 3.5 成长系统

- 📚 **书店日志**: 记录每次推荐（谁来了、拿了什么书、结果如何）
- 🔓 **书籍解锁**: 高声誉解锁新稀有书籍
- 👥 **关系网络**: NPC之间会互相提及（"李医生说您推荐的书很好"）
- 🏆 **成就系统**: 首次完美推荐 / 连续好评 / 全NPC到访等

### 4.2 林月详细角色卡

- **年龄28岁**，独自带4岁女儿小芸，丈夫在外务工
- **核心困境**: 女儿反复发烧但没钱去县医院，不敢告诉丈夫（工资拖欠三月）
- **深层需求**: 需要"你已经做得够好了"的确认+绝境中坚持的力量
- **最佳匹配**: 《活出生命的意义》| **好匹配**: 《给青年的十二封信》| **一般**: 《小王子》
- **对话特点**: 犹豫沉默，不会直接说困难（需选项引导），被关心后慢慢敞开

### 4.3 陈伯详细角色卡

- **年龄68岁**，修钟表45年，孙子不想学修表想学编程
- **核心困境**: 手艺断传，觉得自己不再有价值
- **深层需要**: 理解"价值不只是传承"，一生都有意义
- **最佳匹配**: 《匠人》| **好匹配**: 《月亮与六便士》| **一般**: 《瓦尔登湖》
- **对话特点**: 话少短句，聊往事侧写，不太表达情感

### 4.4 小明详细角色卡

- **年龄14岁**，初二学生，成绩中等偏下，父母期望极高
- **核心困境**: 喜欢画画但被父母撕掉画，觉得没人理解
- **深层需求**: "你的热爱有价值"+ 安全表达自我的出口
- **最佳匹配**: 《小王子》| **好匹配**: 《窗边的小豆豆》| **一般**: 《三体》
- **对话特点**: 防御性强（攻击性话语保护自己），被认真对待后快速软化

### 4.5 李医生详细角色卡

- **年龄42岁**，全镇唯一全科医生，24小时待命18年
- **核心困境**: 怀疑自己在救人还是当"开药机器"，老人延误死亡后内疚
- **深层需求**: 被提醒"每件小事都有意义"+找到对抗倦怠的支撑
- **最佳匹配**: 《当呼吸化为空气》| **好匹配**: 《活出生命的意义》| **一般**: 《悉达多》
- **对话特点**: 专业理性回避感性话题，需主动推进才能触及真实感受

### 4.6 方小姐详细角色卡

- **年龄32岁**，上海工作8年后突然回老家
- **核心困境**: 在城市"假装活着"，回来后既不属于城市也不属于家乡
- **深层需求**: 找到"我想要什么生活"+"归属感从何而来"
- **最佳匹配**: 《挪威的森林》| **好匹配**: 《月亮与六便士》| **一般**: 《瓦尔登湖》
- **对话特点**: 表面客气有距离感，试探玩家水平，真诚对待后放下戒备

### 4.7 神秘旅人详细角色卡

- **年龄不确定**，风尘仆仆背旅行包，自称"找一本书"
- **核心困境**: 寻找祖父留下的某个答案
- **触发条件**: 希望>70 且 服务过≥4位不同NPC
- **隐喻意义**: 可能是多年后的玩家/祖父的老友
- **决定真结局是否达成**

## 五、书籍系统设计 — 核心内容载体

### 5.1 设计理念
每本书都是核心内容载体，不是道具。玩家应该能：
1. 了解这本书讲了什么（详细简介200-300字）
2. 看到真实封面图片
3. 理解适合什么人在什么情境下读
4. 游戏结束后产生"我想读这本书"的愿望

### 5.2 书籍交互流程
```
选书面板 → 点击书籍卡片 → 详情弹窗
                              ├── 封面大图(真实封面 180x270)
                              ├── 书名+作者+出版信息
                              ├── 简介(200-300字全文)
                              ├── 分类标签
                              ├── 为什么适合当前顾客(推荐时)
                              └── [确认推荐] [返回列表]
```

### 5.3 封面获取方案
- **首选**: Open Library Covers API: `https://covers.openlibrary.org/b/isbn/{ISBN}-L.jpg`
- **备选1**: Google Books API
- **备选2**: 豆瓣图书封面URL
- **降级**: 精心设计的CSS封面（书名+作者+配色+装饰图案）

## 七、UI/UX 设计规范

### 7.1 视觉风格定位
- **温暖复古书店美学** — 参考《幽灵书屋》《灵魂旅人》的UI质感
- **配色**: 以暖木色、纸张米色、金色为主调
- **字体**: 中文使用思源宋体/PingFang SC衬线模式，英文使用 Georgia/Crimson Text
- **氛围**: 像走进一家真正的老书店——温暖、安静、有故事感

### 7.2 主场景要求 (当前最大缺陷)
主场景不能只是一个窗户！必须包含：

| 元素 | 描述 | 必要性 |
|------|------|--------|
| 大落地窗 | 日/傍晚/深夜动态变化景色 | 必须 |
| 左侧大书架 | 3-4层，摆放着可见的书籍 | 必须 |
| 右侧柜台区域 | 有台灯、收银台 | 必须 |
| 地板 | 木地板纹理，透视正确 | 必须 |
| 天花板吊灯 | 发出暖色光线 | 必须 |
| 装饰细节 | 植物/挂画/地毯/铃铛 | 强烈建议 |
| 环境粒子 | 光柱中漂浮的尘埃微粒 | 建议 |
| NPC站立区 | 清晰的角色立绘位置 | 必须 |
| 店铺招牌/门牌 | "墨香书店"标识 | 建议 |

### 7.3 对话面板规范
- 底部弹出，毛玻璃背景
- 上方显示NPC头像（像素风立绘）+ 名字 + 身份标签
- 中间打字机效果逐字显示对话
- 打字完成后显示选项按钮（如有）
- 点击面板任意位置 = 继续/跳过
- **绝对不能出现点了没反应的情况！**

### 7.4 书籍详情弹窗规范
- 居中大弹窗，宽度max 480px
- 左侧/顶部：真实封面大图（180x270）
- 右侧/下方：书名 + 作者 + ISBN + 出版信息
- 完整简介（200-300字，全部显示可滚动）
- 分类标签（彩色圆角badge）
- 推荐时额外显示"为什么适合TA"
- 底部操作按钮

### 7.5 启动画面规范
- 不能是简陋的文字+按钮
- 需要有：品牌标识（Logo）、游戏标题（精致排版）、背景动画（粒子/书本浮动）、开始按钮（有设计感的样式）、引用语/副标题

## 八、技术架构

### 8.1 文件结构
```
the-last-bookstore/
├── index.html          # 主页面
├── style.css           # 完整设计系统
├── data.js             # 数据层（NPC/书籍/对话/结局）
├── engine.js           # 核心引擎（状态/逻辑/存档）
├── renderer.js         # UI渲染（DOM/动画/面板）
├── game.js             # 主控制器（流程/事件/输入处理）
└── docs/
    └── GDD.md          # 本文档
```

### 8.2 技术约束（比赛要求）
- 纯前端，浏览器可运行
- 无需后端服务器
- 无需构建工具（webpack/vite等）
- 所有资源自包含（CDN图片除外）

### 8.3 AI 融合方案（满足比赛要求至少一处AI创作）
1. AI NPC对话引擎（动态生成个性化反应）
2. AI 世界观生成（崩塌历史线/小镇地图）
3. AI 美术素材（像素立绘SVG/书籍封面）
4. AI 音效配音（环境BGM/翻页音效）

### 8.4 关键交互状态机（必须实现）
```
统一输入状态机:
  idle → typing (打字中, 点击=跳过全文) → waiting (等待中, 点击=触发回调)
  
整个游戏只有一个全局 click handler,
根据当前 state 分发动作, 绝不冲突!
```
