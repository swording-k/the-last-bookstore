## 一、产品定位（30 秒版本）

**「我的书店」**是结局后玩家打开的一个**个人页**，展示 7 天里：
- 推荐了哪些书
- 接待了哪些人
- 哪些书**自己也想读**（这是关键创新点）
- 收到了哪些回信
- 最终的结局类型

**核心设计原则**：
1. **不破坏现有游戏循环**——只读 `Engine.state`，不修改
2. **离线优先**——所有内容本地生成，没有也行
3. **可分享**——一键生成海报/复制文字
4. **可重玩**——看完个人页后玩家想"再玩一遍用别的书"
5. **通往现实阅读的桥梁**——「我想读」列表 = 待读清单

## 二、用户故事（5 个核心场景）

### 故事 1：结局后打开个人页
> 我玩到第 7 天，触发"平凡日子"结局。系统说"故事讲完了"。我看到「打开我的书店」按钮。点开。

**体验**：进入一个温暖的页面（暖色背景 + 书店风格），看到我 7 天的"档案"。

### 故事 2：查看我推荐过的书
> 我接待了林月，推荐了《小王子》；接待了陈伯，推荐了《月亮与六便士》。这些都展示出来。

**体验**：每条记录显示：书封面 + 标题 + 推荐给了谁 + 一段 AI 生成的"1 个月后回信"。

### 故事 3：发现"我想读"列表（⭐ 核心创新）
> 我看到一些书**没有**推荐出去，但我自己被触动了。我能加到「我想读」列表。

**体验**：在结果页（推荐完书之后），多一个「📖 我也想读这本书」按钮。点了之后这本书进入个人页的"我想读"列表。

### 故事 4：把"我想读"带去现实
> 我想读列表里 5 本书。点"复制"按钮，一键复制书名列表。打开微信读书/得到，粘贴搜索。

**体验**：复制按钮 + 文案"复制后去微信读书/得到搜，5 本都是你想读的"。

### 故事 5：分享我的书店
> 我玩完想发给朋友看。点"生成海报"，下载一张书店风格的海报。

**体验**：海报上显示玩家名字、推荐书数、最终结局、几个金句标签。点击下载 PNG。

## 三、技术架构

### 3.1 模块拆分

新增 1 个模块文件 + 1 个数据字段 + 1 个 UI 入口：

| 改动 | 文件 | 类型 | 说明 |

| 新增 | `mystore.js` | 新文件 | 「我的书店」核心模块（数据 + UI + 交互） |

| 修改 | `index.html` | 加 DOM | `<div id="mystore-screen">` |

| 修改 | `renderer.js` | 接入 | `evaluateBook` 后加"我也想读"按钮 |
| 修改 | `llm.js` | 加函数 | `LLM.generateReply(book, npc, onChunk)` — 生成回信 |

### 3.2 数据结构

`Engine.state` 加一个字段：

```javascript
mylist: []  // 玩家标记"我想读"的书，结构：[{ bookId, day, npcId, addedAt }]
```

**为什么用 Engine.state**：现有存档/读档系统会自动保存它，零额外成本。

### 3.4 关键交互流程

#### 流程 A：标记"我想读"
```
玩家接待 NPC → 选书 → 进入结果面板
    ↓
结果面板里多一个 [📖 我也想读这本书] 按钮
    ↓
点击 → Engine.state.mylist.push({bookId, day, npcId, addedAt: Date.now()})
    ↓
按钮变成"✓ 已加入想读" + 显示"你也可以去微信读书搜这本书"
    ↓
继续游戏
```

#### 流程 B：生成回信
```
玩家在个人页点击某本书的 [💌 1 个月后回信]
    ↓
弹出"信纸"面板 + 打字机效果
    ↓
调用 LLM.generateReply(book, npc, onChunk)
    ↓
3-5 秒后显示完整回信
    ↓
玩家可以 [📋 复制] 或 [✕ 关闭]
```

#### 流程 C：生成海报
```
玩家点 [🎨 生成我的书店海报]
    ↓
隐藏其他 UI，纯 HTML 渲染一个 750×1200 的海报
    ↓
用 html2canvas (CDN) 转 PNG
    ↓
触发下载
    ↓
显示提示"长按图片可分享到朋友圈"
```

#### 流程 D：复制待读清单
```
玩家点 [📋 复制待读清单]
    ↓
读取 Engine.state.mylist → 转成文本
    ↓
调用 navigator.clipboard.writeText()
    ↓
提示"已复制 5 本书名 — 打开微信读书/得到搜一搜"
```

## 五、风险预案（比赛现场可能翻车的地方）

| 风险 | 概率 | 应对 |
|---|---|---|
| LLM 不响应/超时 | 30% | 所有 LLM 调用都有 fallback 文案；演示时先用 LLM 跑一次预热 |
| API key 失效 | 5% | README 提示了，**演示前 30 分钟必须换 key** |
| 海报生成失败（html2canvas CDN 加载失败） | 10% | 改为"长按截图"提示，不依赖第三方库 |
| 现场 WiFi 断 | 20% | 个人页是纯本地 + LLM fallback，**断网也能跑** |
| 玩家 7 天都没加"想读" | 20% | 个人页"想读"列表空时显示「去微信读书搜书名」通用 CTA |
| 玩家第一天就触发结局 | 5% | 已有结局系统拦截，7 天后才有 |
| 时间不够，5 小时想放弃回信 | 30% | **回信是最容易砍的功能**——纯本地 fallback 也能展示价值 |
| 评委问"为什么没有 epub 全文" | 80% | 准备好"我们做 AI 解读+引流，**不抢微信读书生意**"的标准答案 |

## 七、不做什么（明确取舍）

- ❌ **不做完整 epub 阅读器**（侵权 + 6 小时做不出来）
- ❌ **不做后端 / 用户系统**（localStorage 够用）
- ❌ **不做微信扫码登录**（要资质）
- ❌ **不依赖额外 CDN**（除了 html2canvas，海报功能可选）
- ❌ **不改 NPC 对话树**（会破坏状态机）
- ❌ **不加新结局**（会和现有 4 结局逻辑冲突）
