# 「书中剧场」沉浸式角色对谈 — 开发方案

> **目标**：给《最后的书店》的书籍详情页新增一个高创意、高演示价值的互动层：玩家不仅能听店主介绍一本书，还能“走进书里”，与书中角色进行自由交谈和卡片式推进。
>
> **推荐演示书**：新增《福尔摩斯探案集》作为侦探推理样例。它是公版经典、人物关系鲜明、现场演示极容易抓住评委。
>
> **版本定位**：这是继「我的书店」之后的下一版核心能力，主打评分表里的 **创意分 28 / 现实价值 14 / 叙事分 14**。

---

## 一、为什么值得做

现在书籍详情页已经有：

- 书封面
- 书名 / 作者 / ISBN
- 简介
- 推荐按钮
- AI 导读按钮

但「AI 导读」本质还是问答。评委看到的是“AI 在解释一本书”，不一定觉得新。

「书中剧场」要把体验升级成：

> 你不是问 AI “这本书讲什么”，而是推开书页，直接和书中的人物说话。

例如玩家点击《福尔摩斯探案集》：

- 进入贝克街 221B 的纸页场景
- 看到三张角色卡：福尔摩斯、华生、雷斯垂德
- 玩家可以点卡片问题：“你发现了什么线索？”“你怀疑谁？”“这件案子最不寻常的地方是什么？”
- 也可以自由输入：“如果我是店主，你会让我注意哪本书？”
- AI 以该角色口吻回答
- 回答不会剧透结局，只会引导玩家理解推理、观察、证据和人物性格

这个功能能把“书库”从静态书架变成可探索的文学角色空间。

## 二、拿奖角度

| 评分维度 | 当前作品 | 加上「书中剧场」后的提升 |
|---|---|---|
| 完成度 | 已有完整 7 天游戏循环 | 书籍详情页新增可被现场操作的阶段性结果 |
| 技术分 | LLM NPC 对话 / 书籍导读 | 多角色 Prompt、上下文约束、卡片式交互、fallback |
| 创意分 | 末日书店 + 推荐书 | “与书中人物聊天”更直观、更有记忆点 |
| 现实价值 | 引导玩家想读书 | 让玩家先和角色建立关系，再产生阅读兴趣 |
| 叙事分 | 主线 NPC 叙事 | 书内叙事成为第二层世界，作品更丰满 |

一句话卖点：

> 《最后的书店》不是把书做成资料卡，而是把每本书变成一个可以说话的世界。

## 三、MVP 范围

第一版不要覆盖 24 本书。先做 **1 本强演示书 + 通用 fallback**。

### 必做

1. 书籍详情页新增按钮：
   - `进入书中剧场`
   - 只要书有 `bookWorld` 数据，就显示强按钮
   - 没有 `bookWorld` 的书显示普通按钮：`和书中人物聊聊`

2. 新增 `booktheater.js`
   - 全局对象 `BookTheater`
   - 打开沉浸式角色对谈面板
   - 渲染角色卡
   - 渲染卡片式提问
   - 处理自由输入
   - 调用 `LLM.chatWithBookCharacter`
   - 无 Key / 断网时 fallback

3. 新增书籍数据字段 `bookWorld`
   - 第一版给《福尔摩斯探案集》配置完整数据
   - 其他书可后续逐步补

4. LLM 新增接口：
   - `LLM.chatWithBookCharacter(book, character, playerMsg, history, onChunk)`

5. 演示模式支持：
   - `?demo=1` 工具条可以一键打开《福尔摩斯探案集》的书中剧场

### 暂不做

- 不做复杂分支剧情
- 不做案件推理胜负判定
- 不做剧透型“破案”
- 不做 24 本书全部角色
- 不做图像生成场景
- 不做语音对话

### 为什么是福尔摩斯

- 公版角色，版权风险低
- 角色强：福尔摩斯、华生、雷斯垂德都能形成差异化口吻
- 侦探推理天然适合互动问题
- 现场演示时评委不用背景知识也能理解
- 不涉及现实政治、伦理风险低

### 6.3 卡片式交谈

卡片不是普通快捷问题，而是“角色可推动的互动”：

- 点卡片后，系统自动发送该问题
- AI 回复后生成 2-3 个后续卡片
- 第一版后续卡片可先静态，不用 AI 生成

示例后续卡片：

- “继续追问证据”
- “换华生解释一下”
- “不要剧透，给我阅读提示”

## 七、交互流程

### 流程 A：从书籍详情进入

```
书架 → 点击《福尔摩斯探案集》 → 书籍详情
  ↓
点击「进入书中剧场」
  ↓
关闭详情弹窗
  ↓
打开 BookTheater
  ↓
默认选择第一个角色：福尔摩斯
  ↓
显示角色开场白 + 三张问题卡
```

### 流程 B：切换角色

```
点击华生角色卡
  ↓
对话区显示华生开场白
  ↓
问题卡替换成华生的 promptCards
  ↓
历史保留，但当前发言角色改变
```

### 流程 C：自由输入

```
玩家输入：“我怎么训练观察力？”
  ↓
LLM.chatWithBookCharacter(book, holmes, text, history, onChunk)
  ↓
流式显示回复
  ↓
history 记录 user / assistant
```

### 流程 D：无 Key fallback

```
无 API Key / 网络失败
  ↓
根据 character.id 和关键词走本地模板
  ↓
仍然显示角色口吻回复
```

## 十、LLM Prompt 设计

### `chatWithBookCharacter`

系统提示词：

```text
你正在扮演一本书中的角色，与《最后的书店》的玩家对话。

书籍：《{book.title}》
作者：{book.author}
书籍简介：{book.blurb}

你扮演：{character.name}
身份：{character.role}
语气：{character.tone}
目标：{character.goal}

规则：
1. 用第一人称说话，像角色本人，不要说“作为 AI”。
2. 每次回答 1-4 句话，适合游戏聊天气泡。
3. 不要直接剧透原作关键谜底或结局。
4. 可以引导玩家观察线索、理解人物、产生阅读兴趣。
5. 如果玩家问超出书本的问题，把回答拉回书中主题。
6. 语气要鲜明，福尔摩斯要锋利，华生要温和，雷斯垂德要务实。
```

用户消息：

```text
玩家问：{playerMsg}
```

## 十一、Fallback 设计

第一版 fallback 不需要聪明，但必须像角色。

### 福尔摩斯

关键词：

- `线索 / 证据 / 观察`
  - “先别急着下结论。把你看见的事实按顺序放在桌上，答案通常已经在其中。”
- `怎么读 / 阅读`
  - “读推理小说时，不要只追谜底。注意作者让你忽略了什么。”
- 默认
  - “有趣。多数人先解释，少数人先观察。你愿意做后者吗？”

### 华生

- `福尔摩斯`
  - “他有时显得冷淡，但那只是因为他的注意力已经跑到细节深处去了。”
- `适合谁读`
  - “适合愿意慢下来的人。推理故事真正迷人的，是你和作者一起走进迷雾。”
- 默认
  - “如果这本书让你开始注意身边的小事，那它已经起作用了。”

### 雷斯垂德

- `警方 / 误判`
  - “我们不是没有证据，而是太容易相信第一个看起来合理的解释。”
- `案件`
  - “案子最麻烦的地方不在血迹，而在每个人都以为自己看见了真相。”
- 默认
  - “别让漂亮的推理遮住事实。先把证据摆出来。”

## 十三、现场演示脚本

建议插入在“书籍推荐”后：

> “刚才我们把《活出生命的意义》推荐给林月，这是书影响现实角色的一面。
>
> 但书本身也不应该只是简介。比如这本《福尔摩斯探案集》，我可以直接进入书中剧场。”

动作：

1. 打开书架
2. 点击《福尔摩斯探案集》
3. 点击「进入书中剧场」
4. 点福尔摩斯卡片：“你从我身上观察到了什么？”
5. 福尔摩斯回复
6. 切华生：“这本书适合什么样的人读？”

收尾：

> “我们想做的不是电子书阅读器，而是让玩家在读之前先和一本书建立关系。角色先把你带进去，然后你才想真正把书读完。”

## 十四、风险与取舍

| 风险 | 应对 |
|---|---|
| 评委担心剧透 | Prompt 明确不剧透；fallback 也不破案 |
| 版权问题 | 第一版用公版福尔摩斯；不提供原文全文 |
| AI 回答不像角色 | 每个角色有 `tone` 和 fallback，演示时优先预热 |
| 时间不够 | 只做 b25，其他书显示普通 AI 导读 |
| UI 太复杂 | 第一版只做角色卡 + 聊天气泡 + 问题卡 |
| 现场 Key 失效 | fallback 仍可演示角色口吻 |

## 十六、最终验收标准

这版完成后，现场应能在 30 秒内演示：

1. 从书籍详情页进入《福尔摩斯探案集》的书中剧场
2. 点角色卡切换福尔摩斯 / 华生 / 雷斯垂德
3. 点问题卡触发角色回复
4. 自由输入触发角色回复
5. 无 Key 不崩，live Key 更智能

评委能立刻理解：

> 这不是书籍百科，这是一个能让书中人物“活起来”的阅读入口。
